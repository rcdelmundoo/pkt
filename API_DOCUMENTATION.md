## Contributing

### Documentation Guidelines

When adding new APIs, functions, or components, please ensure:

1. **Complete Documentation**: Every public interface should be fully documented
2. **Examples**: Include practical examples for all major use cases
3. **Type Information**: Provide clear type definitions for all parameters and return values
4. **Error Cases**: Document possible error conditions and how to handle them
5. **Performance Notes**: Include any performance considerations or limitations

### Documentation Template

For new APIs/functions/components, use this template:

```markdown
### [Name]

**Description**: Brief description of what this does

**Signature**: 
```[language]
function_signature_here
```

**Parameters**:
- `param1` (type): Description
- `param2` (type, optional): Description

**Returns**: 
- `return_type`: Description

**Example**:
```[language]
// Example usage here
```

**Error Conditions**:
- `ErrorType1`: When this error occurs
- `ErrorType2`: When this error occurs

**Notes**: Any additional notes or performance considerations
```
